AuroraOS Network Stack

Bringing a real NIC to life: a hardened VirtIO-Net transport, an Ethernet framing/dispatch layer, and a full ARP cache with a proper state machine — each built as a small, individually verified increment in QEMU before moving up the stack.

device virtio-net-pci · runtime qemu-system-i386 · net 10.0.2.15 → gw 10.0.2.2 · branch claude/exciting-thompson-7o7pgo
📡
The machine now talks to the outside world. Frames leave and arrive over a real device, and AuroraOS resolves the gateway's MAC by ARP entirely on its own. Crucially, the transport was audited and hardened before any protocol logic — the step amateur kernels usually skip after their first packet, and the one that saves weeks of debugging later. One protocol hop remains before the headline milestone: ping 10.0.2.2.

What this milestone hardened & added

Transport hardening (pre-IPv4 audit)

  • Every device-reported field treated as untrusted id < RX_BUFS · len bounds · copy clamped to min(payload, cap)
  • RX-ring exhaustion: drain-loop recycles every entry a burst of runts can't wedge the ring or mask a good frame
  • IRQ-storm resistant by design ISR only acks + counts; all RX work is polled
  • TX rejects runts/oversize before touching a descriptor
  • Per-interface counters rx/tx packets·bytes·dropped·errors·irqs
  • Surfaced in Settings → System SYS_NETSTAT · NIC up · MAC · drops

Ethernet — Phase 4

  • struct eth_hdr + the seam between driver & stack
  • eth_send(dst, type, payload, len) prepends header, src = our MAC
  • eth_input(frame, len) dispatches by EtherType
  • Runts padded to the 60-byte Ethernet minimum
  • Adding IPv6 later = one new case here; driver untouched

ARP — Phase 5 (a real service)

  • 32-entry cache of {ip, mac, expires, state}
  • State machine EMPTY · PENDING · RESOLVED
  • arp_resolve(ip, mac) hides state from callers the API IPv4 / TCP will use
  • Learns every sender; replies to who-has for our IP
  • 60 s TTL, lazy expiry; PENDING re-asks after 1 s

Discipline

  • DMA without an allocator identity-mapped static buffers: phys == virt
  • Single load-bearing assumption documented in one place
  • No-NIC boot stays graceful "selftest skipped (no NIC)"
  • No GUI regressions verify_drag · SHM stress · host PNG diff
  • Append-only syscall ABI perfus (40) · netstat (41)

Roadmap — logic on top of a proven transport

PCI→ VirtIO-Net→ Ethernet→ ARP→ IPv4→ ICMP Echo→ UDP→ TCP
Next step — Phase 6: IPv4 → ICMP echo
  1. IPv4 RX/TX with header checksum; fragments dropped (no reassembly yet).
  2. Route by destination: on-link via ARP, off-link via the gateway MAC.
  3. ICMP echo request/reply on top.
  4. First real network goal: ping 10.0.2.2 — one test that exercises Ethernet TX/RX, ARP, IPv4, checksum and routing together.
Why ping before UDP/TCP.

A successful echo reply validates the entire lower stack end-to-end in a single round-trip. Only then is it worth building UDP, and TCP last — it typically consumes most of the development time of any hobby OS network stack. After ping, AuroraOS crosses from a local desktop OS into a networked one — a threshold comparable to the jump from text mode to a windowed desktop.
