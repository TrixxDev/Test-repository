AuroraOS 1.1.x

A from-scratch x86 (i686) operating system — preemptive kernel, userspace processes, and a compositing macOS-style desktop. This is a milestone review of the foundation, as built and verified in QEMU.

target i686-elf · runtime qemu-system-i386 · branch claude/exciting-thompson-7o7pgo
✅
The project has cleared the hardest part — building the architectural foundation. The risk is no longer “will the OS boot,” but “how far can it grow.” Every subsystem below is implemented and exercised live in QEMU; regressions (drag/close, SHM stress, byte-identical host renders) pass on each commit.

Subsystems — as built

Kernel

  • Preemptive scheduler + threads
  • Userspace processes · ELF loader · fork / exec / wait
  • Message-passing IPC + named service registry bounded mailbox, kernel-stamped sender
  • Shared memory with refcount + grant model deferred free, no cross-process UAF
  • VFS + FAT32 + tmpfs · pipes · loopback sockets
  • Stable syscall ABI append-only numbering
  • User-pointer validation · per-fd access mode · VFS permissions

Graphics

  • Software framebuffer compositor
  • Damage tracking only changed rects reach VRAM
  • Cached background + per-window surface cache
  • Time-driven render loop fixed cadence, decoupled from input
  • True fullscreen menu enter · Esc exit
  • Runtime resolution switching + UI scaling (100–200%)
  • GPU-ready backend abstraction surface backend + frame hooks

Desktop

  • Window Server z-order, focus, drag, traffic-light chrome
  • Dock separate process · launch on click
  • Finder readdir, open, launch
  • Viewer · Terminal · Settings
  • Shared-memory clipboard SHM_PUBLIC · cross-app Ctrl+C/V
  • Aurora system menu About · Settings · Full Screen · …
  • Resize / maximize / minimize (window-shade)

Stability & security

  • SHM stress self-test 200 cycles + cross-proc deferred-free
  • SHM ownership / lifetime audit
  • VFS audit bounds, permissions, FAT32 hardening
  • IPC audit mailbox bounds, registry hijack guard
  • Regression suite verify_drag · host PNG diff

Where to grow next — three directions

Recommended

1 · Networking

Highest value: after HTTP, AuroraOS reaches the outside world — downloads, APIs, updates, an assistant. More new capability than any single graphics feature.

HR timer→ perf→ virtio-net→ ARP→ IPv4→ ICMP→ UDP→ TCP→ HTTP
Polish

2 · Desktop polish

System Monitor · Text Editor · BMP Viewer · file copy / move / delete · drag & drop between windows. Improvements on top of a finished foundation.

Deferred

3 · x86_64

Don’t open the branch yet. Migrate only when i686 actually hurts — >4 GB RAM, a browser, a JIT, large apps. None of those exist today, so the payoff would be negative.

Next technical step — high-resolution timer

Bridges desktop polish and the network stack: it unblocks perf metrics and TCP timeouts/retransmission.

  1. Add RDTSC reads.
  2. Calibrate against the PIT at boot.
  3. Expose uint64_t time_us(void).
  4. Surface FPS · compose · blit · uptime in Settings → System — real numbers instead of feel.
Two i686 gotchas to plan for

① 64-bit math without libgcc. The TSC→µs conversion needs 64-bit /, which the compiler lowers to __udivdi3/__umoddi3 — undefined under -nostdlib. Keep calibration as “ticks per µs” with a small 64/32 helper, or provide those two symbols.

② TSC invariance. Fine in single-core QEMU; on real / multi-core hardware the TSC can drift with CPU frequency — gate on CPUID invariant-TSC or fall back to HPET later.
